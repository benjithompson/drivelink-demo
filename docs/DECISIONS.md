# Decisions

One entry for each decision that changes or adds to [source-plan.md](source-plan.md). Newest first.

## 2026-10-03 — Phase 6: Perfecto tests

| # | Decision | Reason |
| --- | --- | --- |
| D-51 | The app default cloud service is the stateful `drivelink-proto` (id 361664), not `drivelink-mock`. It has the 126 contract transactions plus 5 stateful ones at priority 4, between the scenario band (2–3) and the default band (5–6). `scripts/build-mock.py` builds both (`--target proto`, the default, or `legacy`). The Espresso core suite resets the demo car before each test. | Ben's direction (Oct 4, 2026): a lock or a charge-limit change must show in the next status, as in a real car. A separate service keeps `drivelink-mock` as a fallback. Measured: smoke 299/299, core suite 10/10. |
| D-50 | Autonomous Testing items for DriveLink are in application 227: environment 493, scenarios 1494 and 1496–1502, suite 583. They are named "DriveLink …". The prompts are in `perfecto/autonomous/README.md`. The suite has no policy. A run selects environment 493. | P-04: work inside application 227 and do not change its context. A suite has no environment field. |
| D-49 | The Scriptless tests come from the PAT scenario prompts (D-50). A prompt is plain language: a user goal, or a "Verify …" sentence about what the user sees. It has no package names, test tags, locators or if/then logic. The scenarios set the Demo console scenario in the app and set it back to `default` at the end. | Ben's direction (Oct 3, 2026): PAT needs human-language prompts to make Perfecto AI Scriptless tests, not a traditional test framework. The first version used scripted step lists. A Scriptless test cannot pass instrumentation arguments. |
| D-48 | After a token refresh fails, `AppViewModel.onSignedOut` calls `GarageRepository.noteSessionEnded()`. It sets the login notice and drops the vehicle data, unless the user signed out on purpose. | The core suite showed the bug: `AuthInterceptor` clears the session, and the auth gate removes the screens before their view models can call `expireSession`. The login screen then had no notice (ui-spec requires it). |
| D-47 | The core suite (package `com.drivelink.demo.core`) runs only with the instrumentation argument `baseUrl`. Without it, `DriveLinkTestRunner` adds `notPackage=com.drivelink.demo.core`. Each test signs out, clears the PIN and sets its scenario through `DemoConfig`. Tests that call a local address grant `ACCESS_LOCAL_NETWORK` on API 37. | AGP writes an assumption failure as a failure in the JUnit XML, and CI reads that XML. A test must not depend on the order of the other tests. A plain connected-test install does not grant the permission, and the system dialog pauses the activity. |
| D-46 | Espresso runs on Perfecto through the Perfecto Gradle plugin (`plugin:+`, 26.9 on Oct 3) in a standalone build, `perfecto/espresso/`. `scripts/perfecto-espresso.sh` sends the token, the APK paths and the instrumentation arguments as `ORG_GRADLE_PROJECT_*` variables and masks secrets in the output. The device sets are fixed device IDs in `config-single.json`, `config-pr.json` and `config-matrix.json`. | The plugin uses the old `buildscript` form and must be the latest version; it stays out of the AGP 9 build. The PAG Perfecto server has no Espresso or upload tool. Device selection cannot be set on the command line. |

## 2026-10-03 — Phase 5 stage 2: remaining screens

| # | Decision | Reason |
| --- | --- | --- |
| D-45 | `AppError.displayMessage()` and `AppError.displayMessageWithId()` (in `:core:domain`, `format/Formatters.kt`) are the one source of error text for screens. A rate-limit error with a Retry-After value reads "Too many requests. Try again in N seconds." The id variant adds " (ID <correlation id>)". The helpers in the Home package and in Maps are removed. This amends the wording in D-33. A launch request closes the open sub-screens before it opens its screen. The DriveLink theme sets the container colors that the Material 3 pickers and dialogs use. | Three agents built three copies of the same text. The measured result on a device was a purple time picker and a launch request `screen=home` that restored the sub-screen. |
| D-44 | Sign out asks for a confirmation. The Profile screen shows no phone number. Accuracy on the Maps card is always in meters. | A tap on Sign out by mistake ends the session and the scenario run. `User` in the API has no phone field. D-13 covers distance and temperature only. |
| D-43 | The Demo console never shows or exports an API key value. The editor keeps a stored key when the field is empty. The export leaves keys out. An import keeps the key already stored for the same id. Reset session signs out and sets the scenario to `default`. It keeps the PIN unless the user checks "Also clear the PIN". | Profiles are shared in chat and in files. Keys stay on the device, encrypted. |
| D-42 | `AppPreferences` (in `:core:domain`) holds the theme and the notification switches. `DataStoreAppPreferences` stores them in the one settings DataStore (D-24). The constructor reads the values once, so the first frame uses the saved theme. | Theme must apply at once and without a restart. The first frame must not flash the wrong theme. |
| D-41 | Maps uses osmdroid 6.1.20 with OpenStreetMap tiles. The user agent is the package name. The tile cache is in the app cache directory. The tiles are inverted in dark theme. The vehicle marker is a Compose node that follows the map (the map reports the pixel position on each draw). The screen shows the OpenStreetMap attribution. | No API key is needed. A Compose marker has a test tag and a content description, which UiAutomator and Perfecto can find. A drawn osmdroid marker has neither. |
| D-40 | The Maps card measures the distance from a fixed demo origin (33.6232, -117.9298). The origin is 0.3 mi from the Aurora sample position. The app asks for no location permission. | A location permission adds a dialog and needs a mock location on cloud devices. A fixed origin gives the same number in every run. |
| D-39 | Car Care headline order: overdue item, due item, open recall, else good. Trips group by day in the device time zone. A km user sees EV efficiency in km/kWh and gas-car efficiency in L/100 km. | The worst state is the most useful headline. Day groups follow the clock of the user. D-13 asks for display conversion only. |
| D-38 | Car Care, Schedule Service, Trips and Alerts load through `SelectedVehicleLoader` (package `screenload`). It waits for the shared vehicle state, loads again when the vehicle, profile or scenario changes, and keeps old data when a reload fails. It ends the session on `Unauthorized`. | One tested implementation of the load, retry and session rules for four screens. A screen started by a launch extra has no Home screen to load the shared state first. |
| D-37 | The Alerts screen shows the alerts of all vehicles. Each row names its vehicle. A tap on an unread alert marks it read before the request ends, and reverts on an error. The screen sets the unread count of the Home bell after every load and every mark. | The Home bell counts alerts of all vehicles. One list keeps the count and the screen the same. |
| D-36 | Schedule Service lists all maintenance items, due and overdue items first, then upcoming items, then "Other". No box is checked at the start. | The Aurora has no due item. A list of due items alone would show only "Other". An empty start makes the validation path easy to test. |
| D-35 | The API has no field for a time slot or for "Other". The app writes them to `notes`: first the line "Preferred time: Morning (8-11 am)", then the line "Other service requested", then the text of the user. The user can type 400 characters, so `notes` stays under the limit of 500. `itemIds` holds the checked items and is null when only "Other" is checked. | `ServiceRequestCreate` has `serviceCenterId`, `preferredDate`, `itemIds` and `notes` only. The contract stays as it is. |
| D-34 | Sliders use `DlSlider` (`remote/DlSlider.kt`) with a round 22 dp thumb. | The default Material 3 thumb is a thin vertical bar. At 10 min on Remote Start it looked like a stray line. |
| D-33 | A rate-limit error card and banner add the wait when the server sent `Retry-After` (wording: see D-45). Scrolling screens (Home, Status, Charging, Charging Schedule, and the screens of D-38) end with a 64 dp spacer. | The user needs the wait time. The scenario chip covered the last row on Home. |
| D-32 | `GarageState` holds the charge settings of the selected vehicle. The Charging and Charging Schedule screens use one copy. After a successful PUT, the app keeps the values it sent, not the answer. The Charging screen saves the limits 500 ms after the last slider move. A failed save puts the sliders back to the saved values. | The mock answers every PUT with the same body. The screens must show the values that the user set. The 500 ms wait avoids one PUT for each step of a drag. |
| D-31 | Every load in `GarageRepository` takes a token (a generation number and the profile and scenario key). A load that ends after sign-out, a vehicle switch, or a profile or scenario change finds an old token and drops its result, also its error. | A refresh that ends after sign-out filled the state again. A late `Unauthorized` could end a new session. |
| D-30 | Amends D-28. After a LOCK, UNLOCK, START, STOP, CHARGE_START or CHARGE_STOP command succeeds, `GarageRepository` keeps the commanded state (lock, climate and engine, charging) on top of the fetched status. The override ends when a fetched status shows a different value than the value at command time. The app clears all overrides on a vehicle switch, a profile or scenario change and sign-out. After CHARGE_STOP, a plugged-in car shows the state `SCHEDULED`. | The mock returns one fixed status body. Without the override, the Lock tile would not change after a command. Measured on the emulator: the Lock tile and the chip change after Done. |

## 2026-10-03 — Phase 5 stage 1: Login, Home, remote commands

| # | Decision | Reason |
| --- | --- | --- |
| D-29 | `MainActivity` uses `launchMode="singleTop"`. The launch extra `command` is removed. A `scenario` extra stores the demo scenario and clears the command card. Without a session, only `console`, `gallery` and `login` open. | `am start` on a running app must reach `onNewIntent` (Phase 4 open issue). The Design Gallery shows every command stage. |
| D-28 | The Lock tile sends LOCK when the status says unlocked and UNLOCK when it says locked. The gas-car Fuel tile opens Vehicle Status. After a command succeeds, the app reloads the status. The mock returns fixed bodies, so the tile can show the old state after a command. | The tile shows the vehicle state, not the last command. The fixed bodies are a limit of the mock (see api.md, "Command type in responses"). D-30 amends this: the tile now shows the commanded state. |
| D-27 | `GarageRepository` (`:core:data`) holds the shared vehicle state. `RemoteCommands` (`:app`) holds the pending and running command. Both are singletons. A change of profile or scenario discards the old status. | The command goes on while the user moves from the PIN screen to Home. All screens read one source for the selected vehicle. |
| D-26 | The first sign-in asks for a 4-digit PIN. The device stores a salted SHA-256 hash in the settings DataStore. The PIN prompt checks the PIN on the device, then sends it in the command body (D-07). Sign out keeps the PIN. | The server cannot check the PIN in the demo (`INVALID_PIN` is documentation only). A local check gives the PIN prompt real behavior. |

## 2026-10-03 — Phase 4: App scaffold and network core

| # | Decision | Reason |
| --- | --- | --- |
| D-25 | The app does not log `cold_start_ms` when `DemoConfigActivity` starts the process. A test runs `am force-stop` after the config step and before it measures a cold start. | A start by the config activity is not a user cold start. |
| D-24 | The settings DataStore is one process-wide instance. | Hilt tests create a new component for each test. DataStore does not allow two active instances for one file. |
| D-23 | The app declares `ACCESS_LOCAL_NETWORK` and asks for it when the active profile host is a private or local address. Automation grants it with `adb install -g` or `pm grant`. | Measured on the API 37 emulator: without this permission, every connection to 10.0.2.2 timed out. This also applies to a private-location mock on a LAN and to Perfecto devices with API 37. |
| D-22 | Enums in the models are strict. An unknown enum value fails the decode and gives `AppError.Parse`. Only `Problem.code` stays a string. | The contract test finds drift at build time. The `bad-payload` scenario shows the Parse error state. |
| D-21 | `apiCall` creates the correlation id before the call and passes it to OkHttp as a request tag. GET retries and the retry after a token refresh keep the same id. | An error then shows the exact id of the request that failed, also for a transport error (D-17). |
| D-20 | Retrofit methods return the raw response body. `apiCall` decodes it with `DriveLinkJson` and maps every error to `AppError`. | Parse errors keep the response and the correlation id. The app never crashes on a malformed body. |
| D-19 | The API models are `@Serializable` classes in `:core:domain`. The app has no separate DTO layer. | The contract test checks the models against all examples. A second layer would double 18 operations of mapping code for a demo. |
| D-16a | Amends D-16. The timeouts apply to each attempt: connect 10 s, read 15 s, write 15 s. The OkHttp call timeout is 35 s, so one GET retry fits in it. | With a call timeout of 15 s, a stalled first attempt uses the whole budget and the retry never runs. |

## 2026-10-02 — Phase 3: Service virtualization

| # | Decision | Reason |
| --- | --- | --- |
| D-18 | `scripts/build-mock.py` uses the SV REST API, not the SV MCP. The MCP stays for interactive checks. | The MCP cannot set priority or a think-time range. CI (Phase 8) runs the same script. |
| D-17 | The app creates `X-Correlation-Id` for each request and shows its own value. It does not expect the server to echo it. The `correlationId` in problem bodies stays as the server value. | SV does not echo request headers without templating. The local mock echoes it; the app must not depend on that. |
| D-16 | Network timeouts: `smoke.sh` uses 20 s per request and one retry after a transport error. Phase 4: OkHttp call timeout 15 s; one retry for GET after a transport error; no automatic retry for POST commands. | SV stalled some requests for 60–100 s (measured in 4 sessions, more than 1,200 requests). The cause is unknown. |

## 2026-10-02 — Phase 2: API contract

| # | Decision | Reason |
| --- | --- | --- |
| D-15 | The local mock answers an unknown `X-Scenario` value with 400. BlazeMeter SV answers it with the default data. | SV has no "header value not in list" matcher for the whole service. The app sends only catalog names. |
| D-14 | `index.json` carries the SV transaction fields: `url`, `urlRegex`, `priority` (bands 1–3 for scenarios, 4–6 for default) and `thinkTimeMs`. Phase 3 adds a copy of the default transaction for each scenario whose think time is not [300, 800] (`fast`, `auth-expired`, `rate-limited`, `server-error`; `slow-vehicle` for polls). | The SV check (Oct 2, 2026) showed that SV supports all the matchers. A default transaction keeps its own delay when it answers another scenario. |
| D-13 | Units: the API sends imperial values only (mi, psi, °F). The app converts the values to km and °C. The °C stepper range is 17–28. | The mock needs only one data set. `User.units` is a display preference. |
| D-12 | `Retry-After` is on 429 only. The spec has no 503 response. | The source plan mentions 503, but no scenario uses it. |
| D-11 | Digital Key, Roadside Assistance and Subscription stay static Menu rows. They have no endpoints. | No scenario or test uses them. Digital Key needs NFC or BLE, and cloud devices cannot demonstrate it. |
| D-10 | `heatedSeats` stays an integer 0–3. In Phase 5, the Remote Start UI changes from a switch to a level selector. | The reference app has seat levels. |
| D-09 | The gas car (ICE) has its own examples for trips, maintenance and location. The scenario status examples apply to the EV only. An unknown VIN gets 404 on status and charge settings. | The vehicle switcher must show consistent data for each car. |
| D-08 | Additive fields: `ClimateState.tempMode`, `VehicleStatus.connectivity`, `ChargingState.state` and `chargerType`, `Tires.lowWheels`, `Location.locality`, `ServiceCenter.phone`, and the Problem codes `INVALID_CREDENTIALS` and `INVALID_PIN`. This entry also records earlier additions that had no entry: the `departure` object (was `departureTime`), `frontDefrost`, `rearDefrost` and `heatedSteeringWheel` (was `defrost`), `Vehicle.trim`, `Location.address`, `ChargingState` `targetPct`, `energyAddedKwh` and `costUsd`, `Trip.efficiencyUnit`, `Alert.vin`, and the codes `NOT_FOUND` and `INVALID_REQUEST`. | A gap review compared the UI spec with the contract. |
| D-07 | Login uses email and password. Each remote command sends the 4-digit PIN in the body. | The reference app works this way (PIN before every command). The source plan used email + PIN for login. |
| D-06 | `ChargeSettings` has `acTargetPct` and `dcTargetPct` (50–100, steps of 10) instead of one `targetPct`. | The reference app has separate AC and DC sliders. |
| D-05 | Added `GET/PUT /vehicles/{vin}/climate-presets`, command type `LIGHTS`, and `params` for remote start. | The Remote Start and Controls screens from Phase 1 need them. |
| D-04 | `getMaintenance` returns last and next service, the interval and the preferred service center. | The Car Care screen from Phase 1 needs them. |
| D-03 | `getHealth` is outside the error scenarios (`auth-expired`, `rate-limited`, `server-error`). | "Test connection" must show whether the host is reachable, independent of the scenario. |
| D-02 | Examples carry `x-scenario`, `x-match`, `x-vin` and `x-headers`. `api/examples/index.json` is generated from them. | The spec stays the single source for the mock, the smoke test and the app tests. |
| D-01 | The `bad-payload` body is in `api/examples-raw/`, not in the spec. | The lint rule "examples must match schemas" stays on for every other example. |
